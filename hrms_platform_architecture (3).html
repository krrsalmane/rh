Time Management Module
Employee time entries — daily clock-in/out records per employee, linked to work schedule
Required hours calculation — auto-computed from the employee's work contract (e.g. 40h/week, 8h/day) accounting for public holidays
Actual vs expected hours — per day, week and month comparison with colour indicators
Overtime tracking — any hours beyond the contract threshold are flagged and accumulated for payroll or recovery
Missing hours / deficit — negative balance tracked per employee, with optional alerts to manager
Monthly time reports — exportable summary per employee, exportable as PDF or Excel
Work schedule templates — HR defines weekly schedules (fixed, rotating, part-time) and assigns them to employees
Manual override — HR agents can correct or add entries with a mandatory reason field
Absence Tracking Module
Absence declaration — employee or HR declares an absence with date range, type, and initial reason
Justification status — each absence is flagged as Justified or Unjustified; can be updated after review
Supporting document upload (PJ) — HR or employee can attach a medical certificate, court letter, or any supporting file
Absence categories — illness, personal, family emergency, training, unjustified — configurable by HR admin
Impact on time balance — justified absences excluded from missing-hours calculations; unjustified ones deducted
Absence history per employee — full chronological timeline with documents, status changes, and HR notes
Absence analytics — team and company-level rates, trends, categories breakdown for HR reports
Notification workflow — absence triggers notification to line manager; approval or acknowledgement recorded
Leave Management Module
Leave types configuration — paid annual leave, sick leave, maternity/paternity, unpaid, special leave — fully configurable
Leave balance per employee — real-time remaining days per type, with accrual rules (monthly, yearly)
Leave request workflow — employee submits request → manager approves/rejects → HR confirms → balance updated
Calendar view — team calendar showing all leaves to detect overlaps and manage coverage
Carry-over rules — configurable per leave type: how many days carry to next year, expiry dates
Public holiday integration — national holidays automatically excluded from leave day counts
Leave statements — printable leave history and balance statement generated as PDF via Document Engine
HR override — HR can manually credit, debit or adjust leave balances with a reason log
Document Engine — Core Design Principle
The Document Engine is built around separation of template and data. A template is a reusable layout with named placeholders. Data is collected through a dynamic form generated from that template's schema. The engine merges both and produces a PDF. Adding a new document type only requires creating a new template — no code changes needed.

Template Structure
Template metadata — name, category, language, version, active/inactive status, created by, last modified
Placeholder variables — typed fields defined within the template: text, date, number, currency, dropdown, signature block
Auto-populated fields — some variables are automatically filled from the employee profile (name, CNE, address, hire date, etc.) reducing manual input
Conditional sections — parts of the template shown or hidden based on data (e.g. clause shown only for CDI contracts)
Company header/footer — company logo, address, signature zone — configurable in settings and injected in every document
Version control — every template change creates a new version; documents always store the template version used at generation time

Template Builder (for HR Agents)
Rich text editor — HR agents write the document body using a WYSIWYG editor, with formatting (bold, tables, lists, alignment)
Variable insertion toolbar — click to insert a placeholder like {{employee.firstName}} directly in the text
Field schema editor — for each custom variable, HR defines the label, type, whether it is required, and if it can be auto-filled
Preview mode — renders the template with sample data so HR can verify layout before publishing
Publish / archive — active templates appear in the generation form; archived ones are hidden but documents generated with them remain accessible

Key Technical Decisions for Developers
Template rendering — Templates stored as structured HTML/JSON with Handlebars-style variable syntax; rendered server-side for security and consistency
PDF generation — Server-side PDF rendering (headless browser or dedicated PDF library) to guarantee pixel-perfect output regardless of client device
File storage — Generated PDFs and uploaded attachments stored in a dedicated file storage service with access control; never directly in the database
Audit trail — Every write operation (document generation, time entry edit, absence status change, leave approval) is immutably logged for compliance
Multi-company readiness — Data model includes a companyId on all tenant-specific entities, enabling future SaaS multi-tenancy without schema changes
User Roles & Permissions
Super Admin
Full platform access. Manages company settings, user accounts, leave type configuration, public holidays. Cannot be restricted.
HR Agent
Generate & archive documents. Manage employees, absences, leave requests. Build and publish templates. View all time records.
Manager
View team time records and absence calendar. Approve or reject leave requests for their team. Cannot edit employee data or generate documents.
Employee (optional)
View own documents, time records, leave balance, and submit leave requests. Cannot access other employees' data.

Scalability & Extensibility Principles
🔌
Plugin-style document types
Adding a new document type (attestation, amendment, notice) requires only creating a new template in the UI — zero code deployment. The engine is document-type agnostic.
🌐
Multi-language templates
Templates can be duplicated in multiple languages (French, Arabic, English). The generation form selects the language variant based on employee preference or HR choice.
🏢
Multi-company / multi-entity
The data model is designed with company isolation from day one. Each company has its own templates, employees, and settings. Enables future SaaS licensing model.
🔗
API-first design
All business logic exposed through a versioned REST API. Enables future integrations: payroll systems, ERP, biometric time clocks, Active Directory for employee sync.
📊
Modular backend services
Document, Time, Absence, and Leave are independent service modules sharing the same data layer. New modules (payroll, recruitment, training) can be added without touching existing ones.
🔔
Event-driven notifications
Key actions emit events (document generated, leave approved, absence flagged). Notification rules are configurable: email, in-app, or future webhook to external systems.
📁
Employee digital file
Every generated document is automatically filed under the employee's digital record. The employee file becomes the single source of truth for all HR documentation over time.
🔒
Compliance & data retention
Documents and audit logs are retained according to configurable retention policies per document type. Deletion requires admin confirmation and is logged.
